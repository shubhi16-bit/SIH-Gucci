# eRTMAC-NWIS Backend & Model Validation

## A. EXECUTIVE SUMMARY
**Status: 🟡 PARTIAL / PROTOTYPE**

The backend contains a mix of highly robust deterministic logic and deeply flawed ML attempts. 
- The **Planning Engine** and **Similarity Engine** are genuinely functional, mathematically sound, deterministic algorithms.
- The newly pushed **Risk/Prediction Model** is structurally broken, suffers from massive data leakage, uses fabricated labels, and fails at inference time. It should not be used.
- The **FastAPI layer** exists but only exposes the Planning Engine.
- The **WITSML data** is still fundamentally flawed (lacking chronological depth/time continuity).

---

## B. COMPONENT-BY-COMPONENT STATUS

### 1. Planning Engine
**Status:** 🟡 **PARTIAL**
- **What it does:** Generates a 500m grid of candidate well locations in a GeoJSON polygon, uses Ray-Casting for containment, and Haversine distance to reject candidates too close to existing historical wells.
- **Is it ML?** No. It is geospatial math.
- **Real Data:** Uses real Volve metadata (`wellbore_exploration_all.csv`) for spacing constraints.
- **Hardcoded:** No hardcoded mock scores exist. The dummy scores (90, 85, 75) were removed, and it now only returns the `spatial_suitability` score which is mathematically derived from Haversine spacing constraints. ✅

### 2. Similarity Engine
**Status:** 🟡 **VERIFIED / REAL (Data coverage limitation resolved)**
- **What it does:** Ranks historical wells against a target well using a **deterministic Weighted Similarity Index (0–100)** across 4 dimensions: Geographic (0.25), Depth/TVD (0.25), Formation/Jaccard (0.30), Trajectory/Inclination (0.15), Context/field+type (0.05). Weights sum to 1.00. ✅
- **Is it ML?** No. Deterministic heuristic. 100% explainable. ✅
- **Real Data:** Loads from `wellbore_exploration_all.csv` (VOLVE filter). Events from `events.csv`.
- **Data coverage:** 26/26 event wells are now successfully joined. Previously, only 5 Volve exploration wells were visible via raw NPD data. A new normalized dataset (`volve_well_metadata.csv`) was generated by extracting surface coordinates, Total Depth, TVD, and max inclination from real `EDM.XML` records and `ACTUAL` trajectory files. All 26 event wells now have reliable historical context. ✅
- **Bug found and fixed:** `rank_wells()` did not exclude the target well when it is also a historical well. Added `exclude_name` parameter (optional, backward-compatible). Verified: `rank_wells(w, exclude_name=w['name'])` no longer returns the target at rank 1. ✅
- **Known design issue:** `total_depth` is used in both `depth_similarity` and `trajectory_similarity`, giving it an effective weight of ~0.12 instead of 0.075. Not a correctness bug; documented.
- **Score interpretation:** "Weighted Similarity Index (0–100)". NOT a probability. NOT a confidence value. The `%` suffix in `scripts/test_similarity.py` output is a cosmetic misnomer — no code treats the score as a probability. ✅
- **Geological alignment:** Formation similarity uses two well-level fields (`wlbFormationAtTd`, `wlbFormationWithHc1`). This is an approximation — it cannot identify which formation the bit is in at a specific depth interval. Do NOT call it "stratigraphic alignment" in the demo.

### 3. Risk / Prediction Model (OLD - V1)
**Status:** 🔴 **BROKEN / FAKE / SLATED FOR ARCHIVE**
- **What it does:** Attempts time-series rolling predictions using WITSML rows.
- **Why it failed:** Suffers from severe data leakage via random row-level `train_test_split` on overlapping windows, injects fake labels when real events are missing, and fails at inference due to `NaN` rolling aggregations on single rows.

### 3.5. Risk / Prediction Model (NEW - V2)
**Status:** 🟡 **PARTIAL — Infrastructure valid, predictive signal insufficient**
- **What it does:** Depth-Indexed binary classification predicting hazard occurrence in [D, D+25]. Uses real historical events and a fold-restricted Similarity Engine context.
- **Model:** `sklearn.ensemble.HistGradientBoostingClassifier` (NOT XGBoost).
- **Real Data:** 25 Volve wells, ~220 positive hazard checkpoints, no fabricated labels.
- **Leakage:** Six automated assertions PASSED. Context features are generated inside each fold using only training-pool wells. Target well is excluded from its own context.
- **CRITICAL CORRECTION:** A previous run reported ROC-AUC = 0.737. This was caused by fold-level context leakage (features pre-computed before splitting). That result is **retracted**.
- **Corrected 5-Fold CV Results (leakage-free):**
  - HGB: ROC-AUC = 0.543 ± 0.096, F1 = 0.118 ± 0.072, Brier = 0.123 (vs Baseline Brier = 0.061)
  - LR:  ROC-AUC = 0.483 ± 0.070 (below random baseline)
- **Verdict:** The leakage-free model does **not** demonstrate meaningful predictive power on unseen wells. The feature set (geographic distance + absolute-depth alignment) is too coarse. **Not ready for API integration as a predictive model.** The evidence-aggregation pipeline (similarity context + explainability) is correctly implemented and usable as a hazard-history lookup tool.

## C. DATA QUALITY LIMITATIONS
**Status:** ⚠️ **DATA LIMITATION**
- **WITSML Indexing:** We cannot do real-time ML prediction with the current cohort. `15/9-F-1` has timestamps but no depth progression (ROP = 0). `15/9-F-4, -5, -7` have depth progression but no timestamps. 
- **Consequence:** Time-series rolling windows (like those in `extractor.py`) are mathematically meaningless on this data.

## D. INTEGRATION & DATA FLOW
Currently, the components do not seamlessly feed into each other.
**Proposed Architecture Flow:**
1. **Frontend** sends GeoJSON polygon to **API (`/planning`)**.
2. **Planning Engine** returns candidate well coordinates + depth.
3. **Frontend** takes a selected candidate and sends it to **API (`/similarity`)**.
4. **Similarity Engine** returns top 3 matching historical wells and their historical events.
5. (Optional) **Frontend** streams active depth telemetry to **API (`/predict`)** along with the Similarity context vector.
